perf_comparator runtime setup

1. Runtime target

- Python 3.7 is the target production runtime.
- The application runtime is distributed as one file: perf_comparator.py
- Current Python dependency pin:
  - oracledb==2.3.0

2. Offline installation

- Prepare a Python 3.7 environment on the target server.
- Install dependencies from requirements.txt using an internal mirror or pre-downloaded wheels.
- If internet access is unavailable, download the wheel for `oracledb==2.3.0` in advance and install it with:
  - python3 -m pip install --no-index --find-links <wheel_dir> -r requirements.txt

3. OceanBase prerequisites

- `obclient` must be installed on the target server.
- `config.ini` must provide the absolute `obclient` path in `[OCEANBASE_TARGET].executable`.
- `user_string` should follow the same convention used by `~/comparator`, for example:
  - root@sys#obcluster

4. Configuration contract

- Oracle source:
  - [ORACLE_SOURCE]
  - user
  - password
  - dsn = host:port/service_name
  - Unified Audit capture is used automatically when AWR and V$SQL are unavailable

- OceanBase target:
  - [OCEANBASE_TARGET]
  - executable
  - host
  - port
  - user_string
  - password

- OceanBase source capture:
  - [OCEANBASE_SOURCE]
  - executable
  - host
  - port
  - user_string
  - password
  - used when [SETTINGS].source_db_mode = oceanbase

- Optional OceanBase source diagnostic connection:
  - [OCEANBASE_SOURCE_SYS]
  - executable
  - host
  - port
  - user_string
  - password
  - recommended for `source-report` on OB 4.2.5 when ordinary users cannot read `QUERY_SQL`
  - normally use a privileged account such as `SYS@...`

- Example starting point:
  - config.ini.template

- Optional WCR input:
  - [SETTINGS]
  - wcr_path = /path/to/workload_capture_export.jsonl
  - or pass `--wcr-path` on the command line
  - used as a fallback when AWR, V$SQL, and Unified Audit are unavailable

- Optional external diagnostics:
  - `plsql_profile = true`
    - on first use the runtime will attempt `CALL DBMS_PROFILER.OB_INIT_OBJECTS(FALSE);`
  - native OCP mode:
    - `ocp_base_url = https://ocp.tidba.com:3600`
    - auth:
      - `ocp_authorization_env = PERF_OCP_AUTH`
      - or `ocp_username` + `ocp_password_env`
      - or `ocp_username` + `ocp_password`
    - target:
      - `ocp_cluster_id = <clusterId>` and `ocp_tenant_id = <tenantId>`
      - or `ocp_cluster_name = <clusterName>` and `ocp_tenant_name = <tenantName>`
    - `ocp_verify_tls = false` if the deployment currently requires `curl -k`
    - the runtime will query official OCP SQL endpoints such as `topSql`, `slowSql`, and `sql/{sqlId}/text`
    - the runtime generates `Authorization: Basic <base64(username:password)>` automatically when username/password mode is used
    - when IDs are absent, the runtime resolves them through `/api/v2/ob/clusters`
  - `ocp_ash_url_template` / `ocp_qpm_url_template`
    - optional URL templates for OCP or operator-owned proxy endpoints
  - `ocp_auth_token_env`
    - environment variable name holding a bearer token, if required
  - `obdiag_executable`
    - optional obdiag or wrapper executable for severe-regression collection
  - `obdiag_extra_args`
    - extra command-line arguments, with placeholders such as `{sql_id}` or `{run_id}`

5. Security handling

- OceanBase passwords are not passed as plain-text process arguments.
- The runtime writes the password to a temporary obclient defaults file with mode 0600 and cleans it up on exit.

6. Current foundation commands

- Validate config and runtime prerequisites:
  - python3 perf_comparator.py --mode check-config --config config.ini

7. Current supported modes

- `batch`
  - Oracle source:
    - python3 perf_comparator.py --mode batch --config config.ini
  - manual SQL file:
    - python3 perf_comparator.py --mode batch --config config.ini --sql-file input.sql
  - WCR import:
    - python3 perf_comparator.py --mode batch --config config.ini --wcr-path workloads/sample.wcr
  - OceanBase source capture:
    - set `[SETTINGS].source_db_mode = oceanbase`
    - set `[OCEANBASE_SOURCE]`
    - run `python3 perf_comparator.py --mode batch --config config.ini --duration 86400`
    - this polls `GV$OB_SQL_AUDIT` during the capture window and records every observed SQL event into workload JSONL

- `replay-only`
  - python3 perf_comparator.py --mode replay-only --config config.ini --workload workloads/workload_<ts>.jsonl

- `report-only`
  - python3 perf_comparator.py --mode report-only --config config.ini --replay workloads/replay_<ts>.jsonl
  - if OCP or obdiag are configured, top severe regressions can be enriched with external evidence

- `stream`
  - Oracle source only in the current implementation

- `source-report`
  - single OceanBase troubleshooting mode, no Oracle comparison and no target replay
  - requires:
    - `[SETTINGS].source_db_mode = oceanbase`
    - `[OCEANBASE_SOURCE]`
  - recommended:
    - `[OCEANBASE_SOURCE_SYS]` for SQL text backfill on OB 4.2.5
  - example:
    - python3 perf_comparator.py --mode source-report --config config.ini --duration 900
  - when SQL text is hidden from ordinary users, the summary and hints will show a coverage note and recommend enabling `_enable_sql_audit_query_sql=true`
  - SQL text recovery order is:
    - captured `QUERY_SQL`
    - `[OCEANBASE_SOURCE_SYS]` lookup
    - native OCP SQL text lookup
    - template-based OCP fallback
